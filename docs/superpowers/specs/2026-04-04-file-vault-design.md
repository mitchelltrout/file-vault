# FileVault — Design Specification

**Date:** 2026-04-04  
**Status:** Approved

---

## Overview

FileVault is a secure encrypted media vault for Windows. It stores files inside an opaque encrypted container that is invisible to the operating system — filenames, folder structure, and file contents are all hidden. Files are decrypted in memory only, never written to disk in plaintext. A companion Android app (built later) connects remotely to stream media without storing anything on the device.

---

## Components

### 1. FileVault Service (`FileVaultService.exe`)
A Windows Service that runs at startup. It owns all vault operations and is the only component that ever touches the encrypted container. It exposes two interfaces:

- **Named pipe** (`\\.\pipe\FileVaultService`) — local IPC for the Windows UI. ACL'd to the current user only.
- **gRPC over TLS** — streaming API for the Android app, bound on a configurable port. Accessible via Tailscale only; never exposed to the public internet.

The service is designed as a self-contained deployable unit so it can be migrated to a homelab Windows server in the future without architectural changes.

### 2. FileVault UI (`FileVault.exe`)
A WinUI 3 desktop application. Communicates exclusively with the service via named pipe — it never reads vault files directly. Sits in the system tray when minimized. Provides all user-facing functionality: vault management, file browsing, media viewing, and settings.

### 3. FileVault Android (future)
A native Kotlin Android app. Connects to the service gRPC API via Tailscale. Streams media in memory — nothing is persisted on the Android device. Built after the Windows app is complete, but the service API is designed with it in mind from the start.

## Vault Container Format

Each vault is a single `.vault` file on disk. The OS sees one opaque binary file per vault.

```
Offset  Size      Field
------  --------  -----
0       8 bytes   Magic bytes + format version
8       32 bytes  Argon2id salt (unique per vault, plaintext)
40      12 bytes  AES-256-GCM nonce (header block)
52      ~256 bytes Encrypted header block:
                    - Vault display name
                    - Creation timestamp
                    - FS root node pointer
                    - Vault settings flags
[header end]  remainder  Encrypted virtual filesystem
```

**Key derivation:** Argon2id with tunable parameters (default: ~1 second unlock time on modern hardware). Derives a 256-bit key from password + salt.

**Encryption:** AES-256-GCM. Each file chunk in the container uses its own nonce, so corruption in one chunk does not compromise others.

**Virtual filesystem:** An encrypted B-tree index maps the folder/file hierarchy to byte offsets within the container. Files are stored as contiguous encrypted chunks. The service can seek directly to any file without decrypting the full container — required for efficient video streaming.

**Memory safety:**
- Decrypted data is held in pinned memory buffers (`VirtualLock`)
- All decrypted buffers are zeroed when the vault locks
- Nothing decrypted is written to disk, temp files, or the Windows page file

## Multiple Vaults

The app supports multiple independent vault files, each with its own password and container. Vaults are listed in the icon rail. Multiple vaults can be unlocked simultaneously.

**Future:** Decoy password support (a second password that unlocks a limited view of the vault for plausible deniability) is planned but not in scope for v1.

## Vault Locking

Three lock triggers, all configurable independently in Settings:

| Trigger | Description |
|---|---|
| Manual | User clicks Lock in the UI or system tray |
| Idle timeout | Locks after a configurable period with no UI interaction (e.g. 5 min) |
| System events | Locks when Windows screen locks, machine sleeps, or session switches |

On lock (any trigger), the service immediately: zeros all decrypted memory buffers, rejects all in-flight Android streaming requests, closes the virtual FS index, and notifies the UI to show the lock screen.

---

## Android Connectivity

**Transport:** gRPC over TLS.  
**Network:** Tailscale (or compatible WireGuard VPN). The service port is never exposed to the public internet.  
**Authentication:** Time-limited session tokens generated by the Windows UI (pairing via QR code scan). Tokens can be revoked from the UI.

**Streaming:**
- **Images:** Single response, decoded in memory on Android
- **Videos:** gRPC server-side streaming with byte-range support, enabling seek without re-downloading. Android plays directly from the stream buffer — nothing written to disk

When the vault is locked, the service immediately terminates all active Android sessions.

## Windows UI Design

### Layout
- **Icon rail (left, ~44px):** Vault switcher icons + Settings. Clicking a vault icon switches the active vault context.
- **Folder panel (collapsible, ~140px):** Shows the folder tree for the active vault. Supports nested folders to arbitrary depth.
- **Content area (remainder):** File grid or list view.

### Views
- **Grid view (default):** Thumbnail grid. Images show actual photo thumbnail. Videos show a thumbnail frame with a subtle play indicator. Folders show a stacked content preview. Thumbnail size adjustable via scroll wheel.
- **List view:** Filename, type icon, size, date only. No thumbnails, no image previews. Toggled via toolbar button.
- **Fullscreen viewer:** Opens on file click. Image fills the screen with pan/zoom (mouse scroll / pinch). Arrow keys or swipe to navigate between files. Escape to return to grid.
- **Video playback:** Auto-loops. Controls fade in on mouse move, fade out after 2 seconds of inactivity. No visible browser chrome.

### Visual Style
- **Theme:** Dark minimal — pure black background (#000000), dark surface panels (#0a0a0a / #111111), muted text hierarchy
- **Accent:** Single low-saturation accent color for selected state and interactive elements
- **Typography:** System font (Segoe UI Variable)
- **No web renderer** — entirely WinUI 3 native controls and custom drawn surfaces

### Lock Screen
When locked: the entire window shows only a password input on a black background. No filenames, thumbnails, or any vault content visible.

## Service Migration Path

The service is built with separation in mind from day one:

1. **Phase 1 (current):** Service and UI on the same Windows machine. Named pipe IPC is local.
2. **Phase 2 (homelab):** Service installed on homelab Windows server. UI on a separate machine connects to it via the gRPC interface (same interface used by Android) over Tailscale. Named pipe is replaced with a networked gRPC channel authenticated the same way as Android.

No architectural changes are required for Phase 2 — only configuration.

## Technology Stack

| Component | Technology |
|---|---|
| Windows Service | C# / .NET 8, Windows Service host |
| Windows UI | C# / WinUI 3 (Windows App SDK) |
| IPC | Named Pipe (System.IO.Pipes) + MessagePack |
| Android API | gRPC (google.golang.org/grpc / Grpc.AspNetCore) + TLS |
| Encryption | AES-256-GCM via .NET `System.Security.Cryptography` |
| Key derivation | Argon2id via `Konscious.Security.Cryptography` |
| Android App | Kotlin, native Android (future) |
| Remote networking | Tailscale / WireGuard |

---

## Out of Scope (v1)

- Decoy password / plausible deniability
- Android app implementation
- Cloud sync or backup
- File sharing between users
- Web UI of any kind
- Homelab server migration (architecture supports it; not implemented in v1)
